# ADR-0003 · offer体检 报告来源可点击：段内内联 + 分维严/中 + 绝不拼链接

- **状态**：采纳（Accepted）
- **日期**：2026-09-23
- **决策人**：用户 + agent（grill-with-docs-pro 流程）
- **关联**：ADR-0001（页面取工商 + 单批并行）；`SKILL.md`「并行调研」「产出」「注意事项」；`assets/report_template.html`
- **关联术语**：见 `references/glossary.md`（来源台账 / 真访问 URL / 严·中·无链接口径 / 主来源）

## 背景（Context）

报告此前只在头部放**一条**可点的招聘主来源链接，七个维度的出处只在正文散文里点名平台（"企查查、天眼查、裁判文书网……"），读者无法一键跳到证据页。用户要求在报告中加入**可点击跳转到对应页面**的数据来源。

核心张力：本技能头号红线是「不得编造」。一个「数据来源链接」只有在该次运行**真的访问/检索到过那个 URL** 时才诚实，否则就是把臆造的 URL 伪装成出处，比不放链接更糟。因此「加可点链接」不是纯模板改动，它牵动调研阶段的数据留痕方式。

实测约束：
- 硬红线四维（待遇 / 参保 / 仲裁 / 套路）多数经 WebFetch / browser-skill **真正打开**过页面（职位页、工商年报页、司法页），天然有真 URL。
- 软维（网络 / 抖音 / 高德）常只有 WebSearch 摘要或 App 内容，未必有干净的独立落地页。
- 参保在工商年报 / 国家公示系统、不在 JD 页（P0-2）；抖音 / 高德常无公司专属口碑。

## 决策（Decision）

采用 **「段内内联来源行 + 结构化来源台账 + 分维严/中保真 + 缺则标无链接、绝不拼链接」**：

1. **位置 = 每段内联**：一~七各维度区块底部加一行「来源：」，结论与出处就近对应。**不设末尾汇总附录**（曾候选，用户否）。
2. **覆盖 = 全部已跑维度**：跑了的维度都要有来源行；未跑维度沿用「未跑（原因）」，不出来源行（模板 `.sources:empty{display:none}` 自动隐藏）。
3. **保真 = 分维严/中**（用户选 ABC 结合）：
   - **硬红线四维（待遇 / 参保 / 仲裁 / 套路）从严**：只挂本次**真正抓取 / 打开过**的页面 URL。
   - **软维（网络 / 抖音 / 高德）从宽**：可挂作为结论直接依据、且工具**确实返回过**的来源 URL。
   - 任何口径下**不拼「平台搜索入口」链接**（曾候选回退方案，用户否——入口 ≠ 证据页，且易被误当成已核验来源）。
4. **缺链接呈现**：维度跑了但拿不到合格 URL 时，显示平台名**纯文本** + 灰色「（无链接）」，不整行隐藏、不省平台名。
5. **来源台账（贯穿工作流）**：调研阶段维护结构化 `{维度, 平台名, URL, 依据类型(已打开/仅检索)}`；渲染与严/中校验都以台账为准——硬维仅接受「已打开」，软维接受「已打开 / 仅检索」，其余降级为「（无链接）」。
6. **样式**：友好标签（如 `天眼查 · 2025 年报`）而非裸 URL；一段可列多个平台链接；一律 `target="_blank" rel="noopener"` 新标签打开。
7. **主来源**：头部那条保留 = 职位页；顶部四张信息卡（职位/薪资、工作地点、公司简介自称、工商登记实况）不放链接，出处归一到对应段。第八段（推荐指数与风险提示）不单独挂来源行。

## 后果（Consequences）

- **正面**：每条结论可一键跳证，报告可信度与可核验性显著提升；台账让「不编造 URL」从口号变为可校验的数据结构；严/中分维既守住硬证据红线，又让软维尽可能给出入口。
- **成本 / 负面**：调研阶段多一层留痕义务（记台账）；受 P0-2 与抖音/高德无独立页影响，部分维度会诚实地显示「（无链接）」，链接覆盖率天然 <100%（这是正确性优先的有意取舍，不视为缺陷）；软维「仅检索」URL 仍是搜索结果、未必等于最终证据页，措辞上以「来源」而非「已核验」呈现。
- **未变**：评分算法、页面取工商、单批并行、硬红线早停仅裁剪报告等核心结构不变；来源行不进入星级计算。
