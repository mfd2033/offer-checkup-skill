# ADR-0003 · offer体检 报告来源可点击：段内内联 + 分维严/中 + 绝不拼链接

- **状态**：采纳（Accepted）
- **日期**：2026-09-23
- **决策人**：用户 + agent（grill-with-docs-pro 流程）
- **关联**：ADR-0001（页面取工商 + 单批并行）；`SKILL.md`「并行调研」「产出」「注意事项」；`assets/report_template.html`
- **关联术语**：见 `references/glossary.md`（来源台账 / 真访问 URL / 统一来源硬标准 / 未获取到可核验来源 / 主来源）

## 背景（Context）

报告此前只在头部放**一条**可点的招聘主来源链接，七个维度的出处只在正文散文里点名平台（"企查查、天眼查、裁判文书网……"），读者无法一键跳到证据页。用户要求在报告中加入**可点击跳转到对应页面**的数据来源。

核心张力：本技能头号红线是「不得编造」。一个「数据来源链接」只有在该次运行**真的访问/检索到过那个 URL** 时才诚实，否则就是把臆造的 URL 伪装成出处，比不放链接更糟。因此「加可点链接」不是纯模板改动，它牵动调研阶段的数据留痕方式。

实测约束：
- 硬红线四维（待遇 / 参保 / 仲裁 / 套路）多数经 browser-skill（`bsk`）**真正打开**过页面（职位页、工商年报页、司法页），天然有真 URL。（本条初版并列写了 WebFetch；ADR-0004 后页面抓取仅走 bsk。）
- 软维（网络 / 抖音 / 高德）常只有 WebSearch 摘要或 App 内容，未必有干净的独立落地页。
- 参保在工商年报 / 国家公示系统、不在 JD 页（P0-2）；抖音 / 高德常无公司专属口碑。

## 决策（Decision）

采用 **「段内内联来源行 + 结构化来源台账 + 统一来源硬标准（无真来源即不下结论、降级未获取到）+ 绝不拼链接」**：

> **2026-09-23 修订**：初版按「硬维严 / 软维中」分维保真、缺链接处以「（无链接）」并列于自信结论旁。用户指出这造成不一致（有的能点开证据、有的写着结论却说无链接），要求「一视同仁、都要有数据支撑」。据此**取消严/中分档**，改为所有维度**同一条硬标准**。

1. **位置 = 每段内联**：一~七各维度区块底部加一行「来源：」，结论与出处就近对应。**不设末尾汇总附录**（曾候选，用户否）。
2. **统一来源硬标准（对所有维度一视同仁）**：任何**给出自信结论**的维度，其来源行**必须**至少挂一条**本次真正抓取 / 打开过**的页面 URL。**取消硬维/软维分档**——搜索摘要、工具返回但未打开的 URL **一律不算数**（要用就必须先打开）。
3. **无合格来源即不结论（降级，而非“有结论+无链接”）**：某维度确实拿不到可打开的权威来源页时，**不得**摆出“看起来有据”的分析段落；改按其**证据不足**处理——徽标标「未获取到可核验来源」，正文写明原因（如平台无公开页 / 登录墙 / 反爬），来源行留空由模板 `.sources:empty` 隐藏。杜绝“跑了→给自信结论→来源写无链接”这种不一致。
4. **绝不拼链接**：任何情况都不造「平台搜索入口」等 URL 充数；入口 ≠ 证据页。
5. **来源台账（贯穿工作流）**：调研阶段维护 `{维度, 平台名, 已打开URL}`。凡要下结论的维度，调研时**必须真正打开至少一个来源页**并记 URL；只有摘要没打开的，要么补打开、要么该维降级为「未获取到可核验来源」。
6. **样式**：友好标签（如 `天眼查 · 2025 年报`）而非裸 URL；一段可列多个平台链接；一律 `target="_blank" rel="noopener"` 新标签打开。
7. **主来源**：头部那条保留 = 职位页；顶部四张信息卡（职位/薪资、工作地点、公司简介自称、工商登记实况）不放链接，出处归一到对应段。第八段（推荐指数与风险提示）不单独挂来源行。

## 后果（Consequences）

- **正面**：每条**下了结论**的维度都可一键跳证；标准对所有维度一致，读者不会再遇到“有分析却标无链接”的不一致；台账 + “无来源即不结论”让「不编造」与「有据可查」同时成立。
- **成本 / 负面**：调研阶段义务更重——每个要下结论的维度都必须真正打开来源页；抖音/高德等常无公开专属页的软维会更频繁地降级为「未获取到可核验来源」（宁缺毋滥的有意取舍）；部分维度结论覆盖度下降，换来一致性。
- **未变**：评分算法、页面取工商、单批并行、硬红线早停仅裁剪报告等核心结构不变；来源行不进入星级计算。
