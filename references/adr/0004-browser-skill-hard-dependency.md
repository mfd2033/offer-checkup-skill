# ADR-0004 · offer体检 抓取口径反转：browser-skill 硬依赖、全局禁 WebFetch、不可用即停

- **状态**：采纳（Accepted）
- **日期**：2026-09-24
- **决策人**：用户 + agent（grill-with-docs-pro 流程）
- **关联**：ADR-0001（工作流首段抓取）；ADR-0003（真访问 URL / 来源台账）；`SKILL.md`「前置依赖」「链接模式」「来源台账」「注意事项」
- **关联术语**：见 `references/glossary.md`（前置预检 / 真访问 URL）

## 背景（Context）

改版前 `SKILL.md` 把 `browser-skill`（`bsk`）与 `WebFetch` 当作**并列**的两条抓取路径：链接模式第 3 步「browser-skill 不可用 → 回退 `WebFetch` 直接抓 → 仍撞墙再请用户贴职位页文本」，来源台账 / 真访问 URL 定义也写作「WebFetch / browser-skill 真正抓取」。

用户明确要求反转该口径：**如果 browser-skill 不可用，就停止，别用 WebFetch。** 动机是登录墙页（BOSS 直聘等）用 `WebFetch` 抓不到真内容却会「假装抓到」，产出低质、来源不可核验的结论，违背本技能「不得编造 / 无来源即不下结论」的头号红线；与其用一条经常失真的降级链凑报告，不如在依赖缺失时干净地停。

## 决策（Decision）

1. **`bsk` 成为唯一页面抓取手段，全局禁用 `WebFetch`**：任何环节（链接模式职位页、页面取工商、参保补查、各并行维度）的「真正打开 / 抓取页面」一律走 `browser-skill`。
2. **`WebSearch` 保留，仅用于发现 / 定位候选 URL**：不禁止搜索；但搜索摘要不作数，打开必须 `bsk`（延续 ADR-0003 统一来源硬标准）。
3. **前置预检（preflight）**：技能一启动、识别输入的**同时**先做一次 `bsk session start`。链接模式与公司名模式**同受此门约束**。
4. **停止语义 = 直接终止并告知**：`bsk` 命令不存在 / 扩展未加载 / `session start` 失败（browser-skill 整体不可用）时，**直接终止全流程**，向用户说明原因并提示「安装 / 登录 browser-skill 后重跑」；不再发任何抓取调用。
5. **停止边界（防过度终止）**：仅「browser-skill **整体不可用**」才全局停。`bsk` 本身正常、只是某个具体页面撞登录墙 / 反爬时**不停**——该维度按「未核到（登录墙 / 反爬）」降级，其余维度照常并行出。
6. **删除贴文本兜底**：取消「请用户把职位页文本粘贴过来」通道。要跑必须有 browser-skill，无 bsk 环境不支持链接模式。
7. **文档落点**：`SKILL.md` 靠前**新增「前置依赖（强约束 · 不可用即停）」小节**承载 1–6；改写链接模式第 3 步、来源台账、注意事项中原「回退 WebFetch / 贴文本」表述；`glossary.md`「真访问 URL」改为仅 `bsk`，新增「前置预检」术语。

## 后果（Consequences）

- **正面**：不再有「WebFetch 假抓到 → 低质结论」的失真路径；依赖缺失时干净终止而非拖出半份不可信报告；抓取口径单一、可核验性更强。
- **成本 / 负面**：无 browser-skill 环境完全无法使用本技能（含链接模式与公司名模式）；单页登录墙不再有其他抓取兜底，只能等 `bsk` 登录态或该维降级。
- **未变**：评分算法、页面取工商、单批并行、软维 ~3s 超时截断、硬红线早停仅裁剪报告等核心结构不变；`WebSearch` 发现能力保留。
- **历史记录保留**：`tests/fixtures/job-pages/README.md` 的「猎聘/智联可用 WebFetch」描述的是 fixture **当初**的历史抓取方式，属客观记录，**不回改**；ADR-0001/0003 中以「初版并列写过 WebFetch，ADR-0004 后仅 bsk」的括注形式标注演化，而非抹除原文。
