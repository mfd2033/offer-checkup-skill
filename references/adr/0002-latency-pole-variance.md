# ADR-0002 · offer体检 时延优化续：压极点方差，砍软维仅作可选

- **状态**：采纳（Accepted）
- **日期**：2026-09-20
- **决策人**：用户 + agent
- **关联**：ADR-0001（页面取工商 + 单批并行）；`tests/test_extract_工商.py` 的 B 段
- **术语**：见 `references/glossary.md`

## 背景（Context）

ADR-0001 把单次体检时延压到「七维同批并行、墙钟 = max(七维)」。剩余可优化空间只在「最慢一跳（极点）」。

2026-09-20 用六岗位（京东集团 / 超聚变 / 德之润 / 盛启新程 / 河南牦之鲜商贸行 / 上海东方泵业）各跑一遍全维七维，实测每维 `responseTimeMs`，得到极点分布：

| 岗位 | 全维墙钟(极点) | 标准版(砍抖音+高德)墙钟 | 省时 |
|---|---|---|---|
| 京东集团 | 2648(待遇) | 2648 | 0 |
| 超聚变 | 3791(网络) | 3791 | 0 |
| 德之润 | 2317(高德) | 2232 | 85 |
| 盛启新程 | 4451(套路) | 4451 | 0 |
| 河南牦之鲜商贸行 | 5869(网络) | 5869 | 0 |
| 上海东方泵业 | 5031(抖音) | 3023 | 2008 |

均值墙钟 ≈ 4.0s；标准版 6 次累计省时 ≈ 2.1s（均值 ≈ 0.35s/次），仅上海东方泵业一次省 ~2s 有意义。

**修正 ADR-0001 末段「砍软维」假设的武断判断**：此前仅凭京东单点（抖音 5.6s 为极点）认为「软维从不是可靠极点、砍软维零收益」。本轮实证显示：
1. 极点落软维 4/6 次（网络×2、抖音×1、高德×1），硬维仅 2/6（待遇、套路）——软维实为常见长板。
2. 但「标准版」只砍抖音+高德、**保留网络口碑**，故仅当「抖音/高德本身唯一极点且网络不更慢」才省时（本轮仅 1/6）。
3. 极点**跨轮也变**（京东自身：仲裁 10.6s → 待遇 2.6s），无维度能稳定充当瓶颈。

## 决策（Decision）

1. **默认保持全维**：七维同批并行不因任何维度「常慢」而默认砍除；「砍软维」是覆盖度权衡，仅作显式 `--lite` 选项，由用户按需开启。
2. **进一步压时延的正确杠杆 = 压极点方差**，而非 blanket 砍软维：
   - 优先压缩**硬维度**离群（待遇/仲裁/套路/参保受搜索引擎限流的长尾），例如降 `max_results`、接缓存/预取、错峰；
   - 软维度（网络/抖音/高德）若偶发长尾，用**超时截断 + 降级**（不阻塞主报告）而非永久删除；
   - 保留「标准版(--lite)」作为用户显式选择，语义不变（砍抖音+高德、保网络口碑）。
3. **不引入结果缓存**（沿用 ADR-0001，保新鲜度）；批量/复查场景的时延不优化记为已知妥协。

## 后果（Consequences）

- **正面**：覆盖度恒定（每次全维），省时仅在用户显式 `--lite` 且恰逢抖音/高德极点时兑现；时延主路径不依赖任何「某维必慢」假设，对 run-to-run 方差鲁棒。
- **负面 / 成本**：全维默认下，偶发软维长尾（如河南牦之鲜网络 5.9s）无法靠默认规避，只能靠超时降级缓解；`--lite` 路径的覆盖损失（缺抖音/高德三段）由用户在选项中知情承担。
- **未变**：ADR-0001 的「页面取工商 + 单批并行 + 早停仅裁剪报告」核心结构不变。
